# Wilthy：把 Dela 改造为 BNUZ 学生的 Agent Harness

日期：2026-11-25　状态：待审阅

## 1. 目的

Wilthy 是给北京师范大学珠海校区（BNUZ）学生用的个人 Agent 应用，基于 Dela（上海交大版）fork。fork 是为了复用 Dela 的 Agent 内核、工作台和通用模块，少造轮子。

Wilthy 是**独立应用**：不向上游提交，也不和上游保持同步。所有改动都不影响 Dela。

校园部分要做到：学生用自己的「数字京师·珠海」账号登录一次，就能在应用里看课表、成绩、培养方案进度和教务通知，并用学校邮箱收发邮件；Agent 能读到这些数据，回答「明天几点上课」「还差多少学分毕业」这类问题。

## 2. 目标、非目标、反目标

**目标（第一版）**

- 应用整体改名为 Wilthy：界面文案、应用身份、配置与数据目录、Agent 命令、内部标识都要改。
- 校园服务：
  - CAS 登录
  - 课表，含校历和作息时间换算
  - 成绩，提供页面
  - 培养方案与学分完成进度，提供页面
  - 教务通知
  - 学校邮箱预设
- 上述数据都能经 `wilthy` 命令和 Skill 交给 Agent。

**非目标（第一版不做）**

- 考试安排：要等学校在考前约半个月发布后才能抓取。
- 微信公众号文章聚合。
- 「唐家湾师专」（赞噢）社区接入：没有公开、合规的接口。
- 课程资料平台：雨课堂只由部分老师自愿使用，学校没有统一平台。
- 课堂视频回看：学校没有对应系统。
- 移动端：`core/protocol` 里的移动端协议保持原样，不改也不扩展。
- 向上游 Dela 回馈，或抽象出「多校兼容层」。

**反目标（即使能跑也算失败）**

- 用户的账号密码或授权码被 Wilthy 读取、保存或转发。CAS 必须由用户在登录窗里自己登录；邮箱授权码只经 `safeStorage` 加密保存在本机。
- 测试样例、文档或提交历史里出现真实的学号、姓名或成绩。
- 改名后仍沿用原 Dela 的身份，导致和原版 Dela 互相覆盖配置、数据或自动更新。
- 对学校服务器高频轮询。同步只在用户操作时，或按低频计划进行。

## 3. 约束

- **项目规则**：遵守 `AGENTS.md` 和 `CONTRIBUTING.md` 的「架构」一节，主要有：
  - 分层与依赖规则（`core`、`modules`、`app` 不引用校园模块，例外是两份清单）
  - 默认不用 Effect
  - 界面用 `ui` 组件和 design token
  - 测试少而精
  - 每个提交只做一件事，提交前先格式化
- **`AGENTS.md` 只能由人修改。** 文中的「Dela」字样、目录树和 `sjtu/` 描述由用户自己更新。
- **GPL-3.0-or-later 的义务**：
  - 保留 `LICENSE` 和原作者的版权声明。
  - 在 README 和「关于」页注明「基于 Dela 修改」及日期，对应第 5(a) 条。
  - 发布安装包时同时提供源码。
  - 不沿用 Dela 的 Logo 和品牌素材，README 写明了素材版权归原作者。
- **教务系统的硬性约束**（已用真实账号实测，详见第 6 节）：
  - 青果 KINGOSOFT，返回 GBK 编码的 HTML。
  - 请求必须带同源 Referer。
  - 部分接口需要按页面文件名换取 token。
- **邮箱**：网易企业邮。用户需要先在网页邮箱里开启 IMAP 并生成客户端授权码；用户已确认自己能生成。

| 品牌素材           | `assets/Dela_*`、`build/` 图标、引导动画里的手写字样（`intro-lettering`） | Wilthy 素材（第 8 节）                                                                                                                               |

做法：先人工处理身份层和用户可见层，再用一次性脚本批量替换内部标识，作为单独的提交。批量替换后要全文检查，确认没有误伤第三方依赖名或无关单词。

- **Go helper 的编译**：如果本机没有 Go 1.22，就用仓库里的 `helper.yml` 工作流在 CI 上编译，再把产物提交进 `vendor/`。
- **移动端协议里的 dela 字样**：`core/protocol` 里的标识也一并改名。移动端不在范围内，所以不用考虑兼容；升不升 `AGENT_PROTOCOL_VERSION` 由实现者决定。

`src/app/main/migrations/` 下的旧版数据过渡（`v6tov7` 到 `v17tobaseline`）是为原 Dela 老用户准备的，Wilthy 没有这类用户。**实现者的决定：第一版保留不动**（新装时这些过渡不会触发），是否删除另行讨论。

### 5.2 `bnuz/campus`：CAS 会话

- 保留 `session.ts` 的结构：独立持久分区、登录窗、`campusRequest`、`hiddenCampusLogin`，以及把 session Cookie 加密存成快照。
- Cookie 归属判断：从 `sjtu.edu.cn` 改为 `bnuzh.edu.cn` 及其子域。
- 登录入口：`https://cas.bnuzh.edu.cn/cas/login?service=https%3A%2F%2Fjwxt.bnuzh.edu.cn%2Fcaslogin`。用户在登录窗里自己登录（账号、扫码、手机均可）；跳转到 `jwxt.bnuzh.edu.cn/frame/homes.html` 即视为登录成功。
- `campusRequest` 需要能：
  - 带上 `Referer: https://jwxt.bnuzh.edu.cn/frame/homes.html`
  - 按 GBK 解码响应
- 会话失效的判断：被跳转到 `/frame/errors/405.jsp`，或跳回 `cas.bnuzh.edu.cn`。此时先用 `hiddenCampusLogin` 静默续登，失败再提示用户重新登录。已实测同一会话内静默续登可行；登录态能保持多久、应用重启后是否还在，在阶段 3 实测并记入提交说明。

### 5.3 `bnuz/timetable`：课表

保留契约、数据表、页面（周视图日历、学期起始日选择器）和 `query_schedule` 命令，重写 `main/api.ts`。

- **学期编码**：保留内部格式 `YYYY-YYYY-N`（N：1 秋、2 春、3 夏）。和教务系统参数的换算：`xn = 起始年`，`xq = N - 1`。当前学期改为调用 `POST /jw/common/showYearTerm.action` 获取，取代按月份推算。
- **课程数据**：调用 `GET /wsxk/xkjg.ckdgxsxdkchj_data10319.jsp?params=<base64("xn=…&xq=…")>`，返回列表形式的 HTML。「上课时间、地点」一列要拆出周次（如 `6-12周(双)`、`1-5,7,9-11周`）、星期、节次和地点；一门课可能有多段时间。
- **学期开始日期**：`POST /public/getDateByTeachingWeek.action?hidOption=FOW&xn=…&xq=…&zc=1&xnq=1` 返回第 1 周周一。同步时自动写入 `semester_start`；保留学期起始日选择器，供手动修正。
- **作息时间**：BNUZ 的节次固定不变，写成常量 `classPeriods`：

  | 节次 | 时间        | 节次 | 时间        |
  | ---- | ----------- | ---- | ----------- |
  | 1    | 08:00–08:45 | 7    | 15:30–16:15 |
  | 2    | 08:55–09:40 | 8    | 16:25–17:10 |
  | 3    | 10:00–10:45 | 9    | 18:00–18:45 |
  | 4    | 10:55–11:40 | 10   | 18:55–19:40 |
  | 5    | 13:30–14:15 | 11   | 19:50–20:35 |
  | 6    | 14:25–15:10 | 12   | 20:45–21:30 |

  第 99 节（11:50–13:20）表示中午。它出现在课程数据里时要能正常显示，不能被当作错误。教务系统也有作息时间接口（`POST /public/SchoolTimetable.show.jsp`），第一版不调用。

- 删除交大特有的研究生课表分支（`graduate.ts`）。

### 5.4 `bnuz/grades` 与 `bnuz/program`：新模块

两个模块都放在 `src/bnuz/` 下，结构与 `timetable` 一致：`contract.ts`、`data/schema.ts`、`main/`、`main/agent/`、`view/`。数据存进 `wilthy.db`，由用户点击同步或在打开页面时按需同步，不做后台轮询。

**成绩（`grades`）**

- **有效成绩**：`POST /student/xscj.chkdgxscjyxxjd_data.jsp`，表单 `sjxz=sjxz1&ysyx=yxcj&zfx=0&xn=…&xn1=…&xq=…&menucode_current=JW130706`，查询范围是「入学以来」。返回的列：学年学期、课程/环节、学分、实得学分、类别、课程性质、考核方式、修读性质、表现形式、综合成绩、课程绩点、辅修标记、备注。
- **原始成绩**：`POST /student/xscj.stuckcj_data.jsp`，`ysyx=yscj`。必须带 token，取法是 `POST /frame/menus/js/SetTokenkey.jsp`，表单 `menucode=xscj.stuckcj.my.jsp`（注意传的是页面文件名）。原始成绩比有效成绩多出平时成绩（过程、技能、期中）和期末成绩。
- **页面**：
  - 按学期分组的成绩表，默认显示有效成绩，可以切换到「原始」查看分项。
  - 顶部汇总：总学分、实得学分、平均绩点（按学分加权，由课程绩点计算；口径在页面上注明）。
- **Agent 命令**：`wilthy query_grades`，可按学期或课程过滤。Skill 里写明：成绩是敏感数据，只在用户询问时读取。

**培养方案（`program`）**

- **理论课程**：`POST /taglib/DataTable.jsp?tableId=2508`，表单 `xh=<学号>&menucode_current=JW130301`。学号从 `showYearTerm.action` 返回的 `userCode` 获取。
- **成绩与培养方案对比**：`POST /taglib/DataTable.jsp?tableId=5327008`，表单 `xh=…&xn=…&xq_m=…&xn1=…&_xq=…&ck_px=akcmk&menucode_current=JW130413`。返回的列：课程模块、课程代码、课程名称、学分、总学时、开设学期、成绩、选课。
- 返回的表格末尾带有 `showTotalRecord('<表格号>','<总条数>')`，用它核对解析出的条数，不一致时提示失败，不要静默丢数据。
- **页面**：
  - 按课程模块分组（如「通识课程/体育与健康类/必修」），每个模块显示已修和应修学分，以及修读状态（已通过、在修、未修）。
  - 另一个标签页按学期列出计划课程。
- 「每个模块应修多少学分」能否从这两个接口得到，要在实现时确认。如果拿不到，就只显示已修学分和课程清单，不要编造要求。
- **Agent 命令**：`wilthy query_program`，返回模块进度和未修课程。

## 6. 测试与验证

- **只给解析器写测试**，覆盖以下几种：
  - 课表的时间与地点拆分（单双周、不连续周次、多段时间、第 99 节）

  - 培养方案的两张表

- **会话失效判断**写一个回归测试：405 跳转和跳回 CAS 两种情况。
- 不对界面写 className 或文案层面的断言；删除随旧模块失效的测试。
- 每个阶段在真实账号上手动走一遍：登录、同步、查看页面、Agent 查询。真实数据不入库，也不进日志。

## 7. 风险

- **CAS 登录态时长未知。** 如果很短，后台同步就会频繁要求重新登录。缓解办法：同步失败时明确提示，不自动重试轰炸。
- **教务系统改版或接口变化。** 解析器要做条数核对和结构检查，失败时给出明确错误。
- **学校对自动化访问的态度。** 条款里写明 Wilthy 是代用户本人访问；请求只由用户操作触发，或低频进行。
